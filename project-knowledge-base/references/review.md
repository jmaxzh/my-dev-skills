# 文档审查流程与注意事项

## 锁定范围

- 按用户指定范围审查：指定 `docs/` 根目录时覆盖全部 Markdown 文档；指定文档时仅审查指定文档。
- 按需读取范围外文档作为证据。不要将其纳入审查结论。
- 根据代码变更反查时，提取变更对象，定位直接引用、行为描述和上层流程文档。

## 操作边界

- 审查时仅报告问题与修订建议。不要修改目标文件。
- 获得修订授权后，按授权范围执行修改。
- 按 `SKILL.md` 的“校验规则变更”和“人工验收”处理确认事项。

## 判定状态

- 验证状态：`通过`、`已确认问题`；尚未验证标为 `未验证`；缺少关键证据、规范性来源未确定或证据冲突时标为 `待确认`，说明原因，不直接判错。
- 仅在根据代码变更反查文档时，另行记录相关性：将有合理影响线索、尚未证实的声明标为 `候选相关`；将已证实受变更影响的声明标为 `已确认受影响`；将已排除影响的声明标为 `明确无关`。另按验证状态判定声明是否正确；不要将受影响等同于存在错误。

## 建立声明清单

- 提取与审查目标相关的可验证声明。按事实类型确定规范性来源并定位证据。
- 区分独立定义、生成内容、摘要和示例。检查定义是否相互冲突、派生内容是否与来源一致。

按事实类型定位来源，不逐项遍历：

- 产品或业务行为：产品规范、业务规则。
- API：OpenAPI、Schema 或协议；CLI：规范或参数定义；配置：Schema 或规范；数据结构：Schema、Migration 或协议。
- 实现结构与执行行为：代码；部署：IaC 或部署配置；外部协议：官方标准或第三方规范。
- 说明性内容：对应规范性来源。

## 判定相关性

仅在根据代码变更反查文档时执行本节：

- 按 `SKILL.md` 的内容边界判断变更对文档的影响；现有说明可能失效时，纳入校验。
- 按“判定状态”记录相关性。继续查证候选相关声明，校验已确认受影响的声明；仅跳过明确无关的声明。
- 证据无法取得时，保留候选相关状态，标记待确认，说明缺失证据，并列入未验证范围。

## 校验声明

- 按声明内容核对定义、默认值、取值范围、作用对象、生效条件、行为及边界。跳过不适用项。
- 按 `SKILL.md` 检查文档规范，按“判定状态”记录结果。

## 处理越界内容

按 `SKILL.md` 的内容边界处理疑似重复定义或实现复述：

1. 核对是否存在影响正确使用或维护的事实错误；证据不足时，标记待确认。
2. 判断内容是否应保留，以及是否应删除、迁移、从规范性来源生成或改为引用。
3. 分别报告事实错误与内容归属问题；不要以其中一项代替另一项。

- 不要从当前实现推定设计约束，也不要要求实现迁就缺乏规范依据的描述。
- 保留规范性定义，建议将独立维护的重复定义改为引用或可校验的派生内容；不要仅因派生内容重复呈现事实而判错。

## 大型审查

- 默认直接审查。文档或证据规模较大、预计需要跨上下文恢复，或需要独立复核时，按需使用分批、子代理或检查点；分别选择，不要强制组合。
- 分批时，按主题关联、内容规模和证据依赖划分批次。维护已审、未审和待确认范围。
- 使用子代理时，分派边界清晰的任务；传入适用规则、必要的用户约定、文件路径和证据线索。并行执行独立任务；顺序执行有依赖的任务。
- 要求子代理返回检查范围、问题、证据位置、待确认项和跨文档关联。由主代理汇总结果、复核跨批次结论。
- 需要恢复审查时，在临时工作目录保存检查点，即进度与证据索引。记录范围、问题、文件路径、行号、必要的声明摘要及跨文档关联；不要复制原始材料或写入 `docs/`。
- 恢复时，读取检查点，核对文件变化，重新检查受影响的结论。

## 交叉复核

- 完成审查后，核对范围覆盖情况；按术语、规范性定义、行为和引用检查跨文档一致性。
- 确认问题前，重新核对原文与规范性来源。检查冲突双方；不要仅凭摘要定论。
- 按需抽查无问题内容。发现系统性遗漏时，扩大复核；发现新证据时，修正已有结论并说明依据。

## 输出结果

- 在当前对话输出最终审查结果。
- 列出审查范围、规范性来源、问题、证据和建议。
- 列出验证结果及未验证范围。根据代码变更反查时，另列相关性状态。

## 注意事项

- 不要按文件名判断权威性。
- 不要把“存在对应实现”视为“文档正确”。
