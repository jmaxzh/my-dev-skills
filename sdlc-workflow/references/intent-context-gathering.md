# 意图相关上下文搜集

- 从可核验事实开始。查阅代码、数据、文件、配置、接口、测试、日志、文档及其他用户指定来源。
- 按用户指定目标搜集；禁止扩展任务目标。允许沿直接依赖补充必要证据；遵守用户明确限定的来源和访问范围。
- 保留可追溯来源。按需记录文件路径、代码位置、接口或字段标识、提交记录、查询条件及记录时间。
- 如实记录观察结果、冲突、缺失和异常，包括无法获取的信息；对冲突和缺失，说明其影响及后续需核验或决策的事项。区分用户表达、观察事实、历史契约与推断；标明依据、验证或确认状态及适用时间，不将未验证内容视为事实或已确认需求，不自行补齐未知信息。
- 按需说明事实与用户已表达目标的关联；已有需求时，标记相关证据。仅执行搜集任务时，不扩展为方案设计或代作未确认的价值取舍。
- 区分业务事实与实现事实。识别系统对使用者或依赖方承诺的行为与约束；将实现细节留作后续阶段参考。
- 不要仅凭当前行为或历史实现认定现行需求。核对适用契约、有效证据或用户确认。不要将技术限制写成产品决策。
- 按任务选择呈现方式，不强制模板。
- 交付事实摘要、来源和不确定性。
- 完成必要核验后交付；不要以消除全部未知项作为搜集完成条件。
