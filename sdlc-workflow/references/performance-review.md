# 性能审查

## 使用条件

- 按用户要求单独执行。
- 将技术方案、代码，或两者作为审查对象。
- 保持步骤独立；不把步骤并入主流程。
- 不实施修改；不执行验收；不替代需求判断。
- 不把审查结论自动设为实施门禁。

## 准备输入

- 读取需求、技术方案、代码、配置、调用链和已有性能指标。
- 标注审查对象、审查范围、工作负载、运行环境和性能目标。
- 区分事实、测量结果、估算、假设和待验证项。
- 记录证据来源、采集时间、负载条件和环境差异。
- 标出证据缺口；禁止编造指标、基准或阈值。

## 审查路径

- 画出端到端调用链。
- 统计 RTT 次数。
- 测量或估算单次 RTT 耗时和累计影响。
- 区分串行等待、并行执行、扇出、排队、重试和超时。
- 检查 MySQL 访问：调用次数、查询耗时、批量化、索引、扫描、锁等待、事务范围和返回数据量。
- 检查 Redis 访问：命令次数、命令耗时、批量化、管道化、缓存命中与未命中、热点 key、数据量、过期和淘汰。
- 检查网络 I/O：请求与响应字节、连接建立、跨地域传输、带宽占用和重试流量。
- 检查磁盘 I/O：读写次数、读写量、顺序或随机访问、同步刷盘、日志和临时文件等待。
- 检查实际涉及的其他 I/O、连接、队列和资源争用。
- 对照基线、目标负载和容量上限；没有基线时标注不可比较。
