# 性能审查

## 使用条件

- 按用户要求单独执行。
- 将技术方案、代码，或两者作为审查对象。
- 保持步骤独立；不把步骤并入主流程。
- 不实施修改；不执行验收；不替代需求判断。
- 不把审查结论自动设为实施门禁。

## 准备输入

- 读取需求、技术方案、代码、配置、调用链和已有性能指标。
- 标注审查对象、审查范围、工作负载、运行环境和性能目标。
- 区分事实、测量结果、估算、假设和待验证项。
- 记录证据来源、采集时间、负载条件和环境差异。
- 标出证据缺口；禁止编造指标、基准或阈值。

## 审查路径

- 根据性能目标、工作负载和已有证据选择审查路径；围绕已发现或有依据怀疑的瓶颈展开检查，证据不足时标注待验证。
- 检查相关计算成本：算法复杂度、热点计算、重复计算、CPU 利用率和并行效率。
- 检查相关内存成本：分配量、对象生命周期、峰值占用、持续增长和垃圾回收。
- 梳理影响性能目标的关键执行路径；涉及跨组件调用时，按需画出端到端调用链。
- 涉及远程调用时，统计往返次数；以 RTT 表示一次网络往返的耗时。
- 区分网络 RTT 与服务端处理耗时；结合串并行关系，测量或估算其对关键路径的影响。
- 区分串行等待、并行执行、扇出、排队、重试和超时。
- 涉及 MySQL 时，检查访问成本：调用次数、查询耗时、批量化、索引、扫描、锁等待、事务范围和返回数据量。
- 涉及 Redis 时，检查访问成本：命令次数、命令耗时、批量化、管道化、缓存命中与未命中、热点 key、数据量、过期和淘汰。
- 实际涉及网络 I/O 且与性能目标相关时，检查请求与响应字节、连接建立、跨地域传输、带宽占用和重试流量。
- 实际涉及磁盘 I/O 且与性能目标相关时，检查读写次数、读写量、顺序或随机访问、同步刷盘、日志和临时文件等待。
- 检查实际涉及且与性能目标相关的其他 I/O、连接、队列和资源争用。
- 对照基线、目标负载和容量上限；没有基线时标注不可比较。
